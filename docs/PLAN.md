# 문신사 CBT 모의고사 웹 서비스 기획서 (개발용 요약본)

기준일: 2026-11-12 · 원본: `docs/reference/기획서_원본.pdf`
이 문서는 원본 기획서를 개발자가 읽기 좋게 옮긴 것입니다. 내용이 다르면 원본 기획서가 우선입니다.

## 1. 개요

문신사 국가시험을 준비하는 수험자가 실제 시험장과 같은 CBT 화면으로 모의고사를 보는 웹 서비스입니다. 관리자가 PDF 문제지를 올리면 문항 단위로 자동 분리되고, 수험자마다 문항 번호와 보기 번호가 다르게 출제됩니다.

| 항목 | 결정 |
| --- | --- |
| 서비스 형태 | 반응형 웹 (PC 우선, 태블릿·모바일 지원) |
| 사용자 | 수험자, 관리자(강사·운영자), 최고관리자 |
| 핵심 기능 | CBT 응시, PDF 문항 분리, 개인별 랜덤 출제, 자동 채점·해설, 관리자 전용 페이지 |
| 기술 스택 | React 정적 화면 + Cloudflare Workers·D1·R2 (모두 무료 요금제) |
| 운영비 | 서버비 월 0원 + 도메인 연 1~3만 원 |
| 1차 출시(MVP) | 최단 4주, 3장의 "필수" 기능 |

출발점: `docs/reference/cbt-demo.html` (화면과 랜덤 출제 로직의 데모). 데모는 문제와 정답이 브라우저에 모두 들어 있으므로, 실서비스에서는 출제와 채점을 서버로 옮깁니다.

전제: 문신사법은 2027년 10월 29일 시행 예정이고, 국가시험의 공식 과목·문항 수·합격 기준은 아직 확인되지 않았습니다. 그래서 과목, 문항 수, 제한 시간, 합격 기준은 코드에 고정하지 않고 관리자가 시험마다 설정합니다.

## 2. 사용자와 권한

| 역할 | 누구 | 할 수 있는 일 | 들어오는 방법 |
| --- | --- | --- | --- |
| 수험자 | 학원 수강생, 개인 응시자 | 시험 응시, 본인 결과·해설 확인 | 시험 코드 + 수험번호 + 이름 |
| 관리자 | 강사, 운영 담당자 | 문제지 업로드, 문항 편집, 시험 개설, 성적 조회 | 허용 목록에 있는 이메일 + 일회용 코드 |
| 최고관리자 | 서비스 운영 책임자 | 관리자 초대·정지, 전체 설정, 접속 기록 조회 | 허용 목록에 있는 이메일 + 일회용 코드 |

관리자 계정은 스스로 가입할 수 없고 최고관리자가 허용 목록에 추가해야만 생깁니다. 수험자는 회원가입 없이 시험 코드로 입장합니다.

## 4. PDF 문제지 업로드와 문항 분리

"자동 분리 후 관리자 검수" 2단계로 처리합니다. 검수를 거친 문항만 문제은행에 들어갑니다. 보기 번호를 섞으려면 지문과 보기 5개를 각각 따로 저장해야 하므로, 문항을 통째 이미지로 자르는 방식은 쓰지 않습니다.

처리 순서:

1. 업로드 — 관리자가 PDF를 올리고 과목·회차를 고른다. 원본은 R2 비공개 버킷에 보관.
2. 텍스트와 좌표 추출 — pdf.js로 페이지마다 글자와 위치를 읽는다(관리자 브라우저에서).
3. 문항 경계 찾기 — 줄 맨 앞의 "1.", "2." 같은 번호로 문항을 나눈다. 2단 편집은 왼쪽 단을 먼저 읽는다.
4. 보기 나누기 — ①②③④⑤ 기호로 지문과 보기를 나눈다.
5. 그림 잘라내기 — 문항 영역 안의 그림·표는 이미지로 잘라 지문에 붙인다.
6. 검수 화면 — 왼쪽 원본 페이지, 오른쪽 분리된 문항. 관리자가 고치고 정답·해설·과목을 입력.
7. 정답 일괄 입력 — "1-③, 2-① …" 형식의 정답표를 붙여넣으면 한 번에 채워진다.
8. 등록 — 검수를 마친 문항만 저장되고, 각 문항은 고유 번호(공통 문항 번호)를 받는다.

| PDF 종류 | 처리 방법 | 단계 |
| --- | --- | --- |
| 텍스트가 살아 있는 PDF (한글·워드에서 저장) | 위 순서대로 자동 분리 | 필수 |
| 스캔본·사진 PDF | 관리자가 화면에서 지문·보기 영역을 드래그로 지정해 이미지로 자름 | 필수 |
| 스캔본 자동 인식 | OCR로 자동 분리 | 2차 |

실제 문제지 샘플은 `docs/samples/`에 넣습니다. 샘플이 없으면 일반적인 형식으로 가정하고, 분리 규칙을 한 파일(예: `src/client/admin/pdf-import/rules.ts`)에 모아 나중에 고치기 쉽게 합니다.

## 5. 개인별 랜덤 출제 (컨닝 방지)

같은 시험이라도 수험자마다 문항 번호와 보기 번호가 다릅니다.

출제 규칙:

- 문항 순서: 응시 시작 시 서버가 수험자별 seed를 만들고 그 seed로 문항 순서를 섞는다. 기본값은 과목 순서 유지, 과목 안에서만 섞기.
- 보기 순서: 같은 seed로 문항마다 보기 순서를 섞는다.
- 섞지 않는 문항: "위 보기 모두", "①과 ②"처럼 보기 위치에 의존하는 문항은 "보기 고정". 하나의 지문에 딸린 묶음 문항은 함께 움직인다.
- 재현 가능: seed를 attempt에 저장하므로 새로고침해도 같은 문제지가 나온다.
- 공통 문항 번호: 결과·해설·통계는 문제은행 고유 번호로 표시한다.

정답이 새지 않게:

- 정답과 해설은 제출 전까지 브라우저로 보내지 않는다.
- 답안은 "몇 번째 문항의 몇 번째 보기"로 보내고, 서버가 원래 보기로 되돌려 채점한다.
- 남은 시간은 서버 시계로 계산한다.
- 한 수험번호는 한 번에 한 기기에서만 응시한다.

랜덤 출제는 옆 화면 번호 베끼기를 막지만, 휴대폰 검색이나 구두 전달까지 막지는 못하므로 교실 감독은 여전히 필요합니다.

## 6. 관리자 페이지 보안

| 장치 | 내용 | 막는 것 |
| --- | --- | --- |
| 허용 목록 | 관리자 가입 화면 없음. 최고관리자가 허용 목록에 넣은 이메일만 /admin 접근 | 아무나 가입 |
| 이메일 일회용 코드 | Cloudflare Access가 /admin 앞에서 로그인 처리. 비밀번호 저장 안 함 | 비밀번호 유출·대입 공격 |
| 서버 권한 검사 | /admin 아래 모든 API가 요청마다 로그인 토큰과 역할 확인 | 주소 직접 입력, API 직접 호출 |
| DB 비공개 | DB와 파일 저장소는 인터넷 주소가 없고 서버 코드로만 접근 | DB 직접 접근 |
| 요청 수 제한 | IP별 요청 수 제한 | 무차별 요청, 무료 한도 소진 |
| 세션 관리 | 로그인 유지 시간 짧게(예: 8시간), 최고관리자가 즉시 차단 가능 | 세션 탈취, 공용 PC |
| 접속 기록 | 로그인, 문항 수정·삭제, 성적 내려받기 기록 | 내부 오남용 |
| HTTPS 강제 | 모든 통신 암호화, 인증서 자동 갱신 | 중간 도청 |
| 파일 검사 | PDF만 허용, 20MB 상한, 비공개 저장소 | 악성 파일, 문제지 유출 |
| IP 허용 목록 | 학원·사무실 IP에서만 관리자 접속 (선택) | 외부 접속 |

## 7. 기술 스택과 시스템 구조

서버비가 들지 않도록 Cloudflare 무료 요금제만으로 구성합니다.

```
수험자 브라우저 ──HTTPS──┐                ┌── 관리자 브라우저 (Access 로그인, pdf.js)
                          ▼                ▼
                Cloudflare Workers (Hono)
                ├─ 응시 API: seed 셔플, 서버 시계, 채점
                └─ 관리자 API: 역할 검사, 문항·시험 관리, 성적, 작업 기록
                          │  (서버 코드로만 접근)
        ┌─────────────────┼──────────────────┐
     Access              D1 (SQLite)          R2
  관리자 로그인       문항·시험·응시·답안     PDF 원본, 문항 이미지
```

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 화면 | React + Vite + TypeScript | 정적 파일 요청은 무료 한도에 포함되지 않음 |
| 화면 구성 | Tailwind CSS + shadcn/ui | 관리자 표·폼 빠르게 구성 |
| 서버 | Cloudflare Workers + Hono | 무료 하루 10만 요청 |
| DB | Cloudflare D1 | 무료 500MB/DB |
| DB 접근 | Drizzle ORM + 마이그레이션 | 변경 이력 관리, 나중에 PostgreSQL 이전 쉬움 |
| 관리자 로그인 | Cloudflare Access | 50명까지 무료 |
| 파일 | Cloudflare R2 | 무료 10GB |
| PDF 처리 | pdf.js (브라우저) | 서버 연산 없음 |
| 배포 | GitHub → Cloudflare 자동 배포 | HTTPS 자동 |
| 오류 추적 | Sentry 무료 | 오류 알림 |
| 테스트 | Vitest + Playwright | 셔플·채점 단위 테스트, 응시 흐름 테스트 |

무료 구성의 제약: Workers 무료는 요청당 CPU 10ms. 무거운 작업은 브라우저에서, 서버는 셔플·채점·저장 같은 가벼운 일만 합니다. 한도가 부족해지면 코드 변경 없이 Workers 유료(월 약 6,700원)로 올립니다.

## 8. 데이터 모델

| 테이블 | 담는 것 | 주요 항목 |
| --- | --- | --- |
| admins | 관리자 계정 | 이메일, 역할(admin·super_admin), 상태, 초대한 사람 |
| subjects | 과목 | 이름, 표시 순서 |
| source_files | 업로드 PDF | R2 키, 회차명, 올린 사람, 처리 상태 |
| questions | 문항 | 공통 문항 번호, 과목, 지문(글·이미지), 해설, 보기 고정 여부, 묶음 번호, 상태(review·active·disabled), 버전 |
| choices | 보기 | 문항, 내용(글·이미지), 정답 여부, 원래 순서 |
| exams | 시험 | 이름, 제한 시간, 합격 기준, 셔플 옵션, 시험 코드, 열리는 기간, 해설 공개 여부 |
| exam_questions | 시험 문항 | 시험, 문항, 배점 |
| attempts | 응시 기록 | 시험, 수험번호, 이름, seed, 시작·제출 시각, 점수, 합격 여부 |
| answers | 답안 | 응시 기록, 문항, 고른 보기, 저장 시각 |
| audit_logs | 관리자 작업 기록 | 누가, 언제, 무엇을, 대상, IP |

수험자별 순서는 저장하지 않고 attempts.seed로 다시 계산합니다. 응시 기록이 있는 문항은 수정 대신 새 버전을 만듭니다.

## 9. 배포와 운영 (사람이 하는 일 포함)

최초 배포 순서:

1. 계정 만들기 — 클라이언트 명의로 GitHub, Cloudflare, 도메인 등록업체 계정. (사람)
2. 도메인 구매 — .kr 또는 .co.kr, 자동 연장. (사람)
3. 도메인을 Cloudflare에 연결 — 네임서버 변경. (사람)
4. D1 DB 2개(운영·테스트)와 R2 버킷 생성, 마이그레이션 적용. (명령은 Claude Code가 준비)
5. GitHub 저장소를 Cloudflare에 연결, main 브랜치 자동 배포. (사람)
6. HTTPS 확인.
7. Cloudflare Access에서 /admin 보호, 최고관리자 이메일 허용 목록 등록. (사람)
8. 오픈 전 점검 — 실제 문제지로 업로드부터 채점까지, 30명 동시 응시, 무료 한도 사용량 측정.

운영 중:

| 항목 | 방법 | 주기 |
| --- | --- | --- |
| DB 백업 | D1 시점 복구(무료는 최근 7일) + 덤프 파일 별도 보관 | 상시 / 주 1회 |
| 복구 연습 | 백업을 테스트 DB에 되살려 보기 | 분기 1회 |
| 장애 감시 | 접속 감시와 Sentry 알림 | 상시 |
| 배포 되돌리기 | Cloudflare에서 이전 배포로 되돌리기 | 문제 시 |
| 라이브러리 보안 패치 | Dependabot 알림 확인 | 월 1회 |
| 시험일 배포 금지 | 단체 응시 시간에는 배포하지 않기 | 시험일 |

법적 준비: 개인정보 처리방침과 이용약관 게시(문구는 클라이언트 확정), 업로드 문제지의 저작권은 클라이언트 책임.

## 10. 비용

서버비 월 0원, 도메인 연 1~3만 원. Workers 무료(하루 10만 요청, CPU 10ms), D1 무료(DB당 500MB, 하루 읽기 500만 행·쓰기 10만 행), R2 무료(10GB), Access 무료(50명).
한도를 넘으면 요금이 아니라 그날 요청이 막힙니다(한국 시간 오전 9시 초기화). 100명 × 60문항 ≈ 답안 저장 6,000건/일로 하루 한도의 약 10%(추정).

## 11. 일정 (최단 4주)

| 주차 | 단계 | 완료 기준 |
| --- | --- | --- |
| 1 | 기반 | 관리자가 이메일 인증으로 로그인해 문항을 손으로 등록·수정. 샘플 PDF 수령, 도메인·계정 준비 |
| 2 | PDF 분리 | 샘플 PDF를 올려 검수를 거쳐 문제은행에 등록 |
| 3 | 응시·채점 | 수험자 2명이 같은 시험에서 서로 다른 문제지를 받고, 제출 후 점수가 맞게 나옴 |
| 4 | 오픈 | 성적 조회·접속 기록, 구매한 도메인에서 30명 동시 응시 시험 통과 |

조건: 샘플 PDF는 첫 주 안에, 클라이언트 회신은 1영업일 안에, 오픈 전 범위 확대 없음. PDF 자동 분리가 늦어지면 영역 직접 지정 방식만으로 먼저 열고 자동 분리는 오픈 뒤에 붙임.

## 12. 변경 대응

- 기능별 모듈: 폴더와 테이블이 나뉘어 있어 한 기능을 빼도 다른 기능이 깨지지 않음.
- 기능 스위치: 해설 공개, 오답 다시 풀기, 보기 셔플은 관리자 설정에서 켜고 끔.
- 설정값 분리: 과목, 문항 수, 제한 시간, 합격 기준은 시험마다 입력.
- DB 변경 이력: 마이그레이션 파일로 관리.
- 자동 테스트: 채점·셔플 테스트로 회귀 확인.

## 13. 리스크와 클라이언트 확인 사항

| 리스크 | 대응 |
| --- | --- |
| 문제지 양식이 제각각 | 샘플로 규칙 조정, 검수 화면, 영역 직접 지정 |
| 스캔본 PDF가 대부분 | 영역 직접 지정으로 시작, OCR 2차에서 앞당김 |
| 무료 한도 초과 | 사용량 알림, 시험 전 확인, 필요 시 유료 전환 |
| 무료 요금제 정책 변경 | Drizzle로 DB 의존 줄여 이전 가능하게 |
| 공식 시험 형식 차이 (4지선다, 실기 등) | 보기 수·합격 기준을 설정값으로 |
| 시험 중 접속 끊김 | 답안 즉시 저장, 재접속 이어서 응시 |
| 관리자 이메일 계정 탈취 | 이메일 2단계 인증, 접속 기록, 허용 목록 즉시 제거 |

클라이언트 확인 항목:

- [ ] 시험 코드 입장인가, 회원가입인가?
- [ ] 학원 교실 전용인가, 집에서도 응시하는가?
- [ ] 문제지 PDF는 텍스트형인가, 스캔본인가? 샘플 2~3개 제공 가능한가?
- [ ] 보기는 5지선다로 고정해도 되는가?
- [ ] 동시 응시 최대 인원은?
- [ ] 관리자 수, 여러 학원(지점) 구분 필요 여부?
- [ ] 도메인 이름 후보와 서비스 명칭은?
- [ ] 해외 클라우드(Cloudflare) 사용 제약이 있는가? 무료 요금제 약관이 이 서비스의 운영 방식을 허용하는가?
