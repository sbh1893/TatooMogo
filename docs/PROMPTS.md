# Claude Code 단계별 지시문

각 단계의 지시문을 Claude Code에 그대로 붙여넣으세요. 한 단계가 끝나면 Claude Code가 멈추고 보고합니다.
보고를 읽고, 실행해 보고, 문제가 없으면 다음 단계로 넘어가세요.

---

## 0단계 — 분석 (코드 작성 전)

```
CLAUDE.md, docs/PLAN.md, docs/reference/cbt-demo.html 을 읽고 분석해 줘.
아직 코드는 쓰지 마.

다음을 정리해서 docs/ANALYSIS.md 로 저장하고 요약을 보여 줘.
1. 이해한 서비스 요약 (5줄 이내)
2. API 목록 초안 (수험자용 / 관리자용, 메서드·경로·요청·응답 요지)
3. 화면 목록 초안 (경로와 들어가는 요소)
4. Drizzle 스키마 초안 (테이블·컬럼·타입·인덱스)
5. seed 기반 셔플과 채점의 설계 (PRNG 종류, 역변환 방법)
6. 기획서에서 모호하거나 서로 맞지 않는 부분, 그리고 각각 어떻게 가정할지
7. 1~4주차 작업을 더 잘게 나눈 체크리스트
```

## 1주차 — 기반

```
docs/ANALYSIS.md 를 기준으로 1주차 작업을 해 줘.

- 프로젝트 뼈대: Vite + React + TypeScript 화면, Hono Worker, wrangler 설정(Static Assets, D1, R2 바인딩)
- npm 스크립트: dev, build, typecheck, lint, test, db:generate, db:migrate:local, db:seed:local
- Drizzle 스키마 10개 테이블과 첫 마이그레이션
- 시드: 데모 20문항(과목 4개)을 로컬 D1에 넣는 스크립트
- 관리자 인증 미들웨어: 운영은 Cf-Access-Jwt-Assertion 검증 + admins 테이블 역할 확인, 로컬은 ADMIN_DEV_EMAIL 우회(development 전용)
- 관리자 화면: 문제은행 목록·검색, 문항 직접 등록·수정(지문, 보기 5개, 정답, 해설, 과목, 보기 고정 여부), 사용 중지
- 응시 기록이 있는 문항은 수정 시 새 버전을 만드는 로직 (지금은 응시 기능이 없어도 규칙과 테스트는 넣기)
- audit_logs 기록 (문항 생성·수정·중지)
- docs/SETUP.md: 내가 Cloudflare에서 해야 할 일(계정, D1·R2 생성, Access 설정, 도메인 연결)을 순서대로
- .gitignore, .dev.vars.example, README 실행 방법

끝나면 멈추고 CLAUDE.md의 보고 형식으로 알려 줘.
```

## 2주차 — PDF 분리

```
2주차 작업을 해 줘. docs/samples/ 에 있는 PDF를 기준으로 맞춰 줘.
(샘플이 없으면 일반적인 2단·5지선다 형식을 가정하고, 그렇게 가정했다고 보고에 적어 줘.)

- 관리자 PDF 업로드: PDF만, 20MB 상한, R2 비공개 저장, source_files 기록
- pdf.js로 브라우저에서 텍스트·좌표 추출 → 문항 경계(줄 맨 앞 번호), 2단이면 왼쪽 단 먼저 → ①~⑤로 지문·보기 분리
- 분리 규칙은 한 파일에 모아 두고 단위 테스트 작성
- 그림·표 영역은 캔버스로 잘라 이미지로 R2에 저장하고 지문에 연결
- 검수 화면: 왼쪽 원본 페이지, 오른쪽 분리 결과 편집, 문항 합치기·나누기
- 정답표 일괄 입력 ("1-③, 2-①" 형식 붙여넣기)
- 스캔본 대응: 원본 페이지에서 지문·보기 영역을 드래그로 지정해 이미지로 자르기
- 검수 완료 문항만 status=active로 문제은행 등록

끝나면 멈추고 보고해 줘. 샘플 PDF로 몇 문항 중 몇 문항이 자동으로 바르게 나뉘었는지도 알려 줘.
```

## 3주차 — 응시·채점

```
3주차 작업을 해 줘.

- 관리자 시험 개설: 문항 선택(과목별 필터), 제한 시간, 합격 기준(과목별 최소 %, 평균 %), 셔플 옵션, 해설 공개 여부, 열리는 기간, 시험 코드 발급
- 수험자 입장: 시험 코드 + 수험번호 + 이름 → attempt 생성(seed 저장). 같은 수험번호 재입장 시 같은 attempt로 이어서 응시, 다른 기기 동시 응시는 막기
- 응시 화면: docs/reference/cbt-demo.html 의 화면 구성(답안 표기란, 글자 크기, 1단·2단, 안 푼 문제 이동, 제출 확인, 모바일 하단 패널)을 React로 옮기기
- 서버 셔플: seed 기반 결정적 PRNG, 과목 안 셔플 기본, 보기 고정·묶음 문항 처리
- 답안 저장: 선택할 때마다 저장(화면 번호 → 서버에서 원래 보기로 변환)
- 서버 시계 타이머, 마감 시 자동 제출
- 채점·결과: 과목별 점수, 과락, 합격 판정. 해설은 제출 후 + 공개 설정일 때만
- 테스트: 같은 seed 같은 순서 / 다른 seed 다른 순서 / 역변환 / 응시 중 응답에 정답·해설이 없음 / 마감 후 제출 처리
- Playwright: 수험자 2명이 같은 시험에서 서로 다른 문제지를 받고 제출 후 점수가 맞는지

끝나면 멈추고 보고해 줘.
```

## 4주차 — 오픈 준비

```
4주차 작업을 해 줘.

- 관리자 응시 현황: 응시 중·제출 완료 인원, 수험자별 진행률
- 성적 조회: 수험자별 점수, 공통 문항 번호 기준 정답률, 엑셀(xlsx) 내보내기
- 접속 기록 조회 화면 (최고관리자만)
- 최고관리자: 관리자 허용 목록 추가·정지
- IP별 요청 수 제한
- Sentry 연동(키는 환경 변수)
- 부하 점검 스크립트: 30명이 동시에 입장·답안 저장·제출하는 시나리오, 요청 수와 D1 읽기·쓰기 수 추정치 출력
- 개인정보 처리방침·이용약관 페이지 자리(문구는 비워 두고 표시)
- docs/SETUP.md 에 배포·운영 절차 보강: GitHub 연결 자동 배포, 운영 마이그레이션, 백업(덤프) 방법, 되돌리기
- docs/OPERATIONS.md: 시험일 체크리스트

끝나면 멈추고 보고해 줘. 오픈 전에 내가 직접 해야 할 일을 마지막에 목록으로 정리해 줘.
```
